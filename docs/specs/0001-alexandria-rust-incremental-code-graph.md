# Spec 0001: Alexandria Rust Incremental Code Graph Infrastructure

## Problem Statement

Maintaining accurate, real-time Code Graphs across dozens of Motorola OEM Android repositories with hundreds of daily Gerrit merges is currently unfeasible with Python `alexandria.py` and batch `graphify extract`. Full extraction takes minutes per run, `graphify update` cannot handle the repository-root versus output-directory split, running full scans can interfere with local working trees in developer IDEs, and relying on external LLM APIs for vector embeddings is computationally prohibitive and risks leaking proprietary OEM secrets.

## Solution

A high-throughput, native Rust daemon (Alexandria) that monitors Gerrit `change-merged` events over an SSH stream, filters out non-code repositories (such as `akashic/*`) to prevent infinite self-trigger loops, processes commits via bare Git object diffing without touching working trees, uses in-process `tree-sitter` parsers with a phased language grammar roadmap (Phase 1: Java/Kotlin; Phase 2: C/C++, AIDL, Protobuf), redacts sensitive secrets in-line via a "Redact & Retain" policy, stores the Code Graph in an embedded SQLite WAL database with companion `sqlite-vec` vectors served by a local TEI sidecar, applies a 5-minute per-repository debounce state machine, notifies Netflix/Orkes Conductor via outbound HTTP webhooks on structural API changes to trigger architectural note reconciliation, and renders `graph.json` projections lazily on-demand.

## User Stories

1. As an OEM Android Developer, I want merged Gerrit changes to reflect in the repository's Code Graph within seconds, so that AI coding assistants and investigations have up-to-date symbol context without manual refreshes.
2. As an OEM Android Developer, I want Alexandria to inspect merged commits without modifying my local working tree or switching my branch, so that background graph indexing never causes git lock conflicts or disrupts my active IDE workspace.
3. As an Autonomous AI Coding Agent, I want to query a fresh `graph.json` projection or SQLite vector index on-demand, so that I can discover affected call chains and callers without waiting for full repository re-indexing.
4. As a Platform Infrastructure Operator, I want Alexandria to automatically discover OEM repositories in my workspace by reading their Git remotes, so that I don't have to manually register every new app checkout.
5. As a Platform Infrastructure Operator, I want incoming merge bursts on high-velocity projects to be debounced sequentially per repository, so that system resources are protected and redundant embedding calls are eliminated.
6. As a Security and Compliance Officer, I want all source snippets to undergo automated secret and credential scrubbing before vectorization, so that proprietary OEM signing keys and tokens never enter vector databases or AI model contexts.
7. As a Platform Infrastructure Operator, I want vector embeddings to be generated by a local inference sidecar using dense code models, so that embedding generation is cost-free, high-throughput, and completely air-gapped from cloud APIs.
8. As a Knowledge Base Maintainer, I want Code Graph state to be stored in an ACID-compliant embedded database with Write-Ahead Logging, so that graph state survives unexpected daemon restarts without corruption.
9. As an Autonomous AI Coding Agent, I want high-level module summaries to be synthesized on-demand using a compact local Gemma model, so that architectural overviews remain grounded in recent structural changes.
10. As a Knowledge Base Maintainer, I want to decouple the Code Graph from the Akashic Vault, so that ephemeral source code changes do not pollute authoritative incident and root cause analysis notes.
11. As a Tool Developer, I want Alexandria to expose a pluggable event ingestion interface, so that the ingestion transport can transition from SSH stream-events to HTTP webhooks without modifying graph reconciliation logic.
12. As an OEM Android Developer, I want Java and Kotlin AST diffs to be calculated in-process via tree-sitter, so that incremental changes incur zero subprocess spawn overhead.

## Implementation Decisions

- **Core Daemon & Concurrency Architecture**: Built as an asynchronous native Rust daemon powered by Tokio, employing per-repository worker channels and actors to debounce merge bursts and enforce sequential, conflict-free graph mutations.
- **Repository Discovery & Configuration**: Discovers local OEM repositories dynamically by inspecting Git remote configurations under designated workspace paths, supporting optional configuration overrides for custom branch filters and exclusion rules.
- **Gerrit Event Ingestion & Self-Trigger Prevention**: Ingests `change-merged` events over an SSH stream (`gerrit stream-events`). Implements strict project filtering to automatically ignore non-code repositories, specifically dedicated Vault repositories matching `akashic/*` or `akashic-*`, preventing infinite self-trigger loops when Vault notes or architectural updates are committed back to Gerrit.
- **Non-Invasive Git Ingestion**: Ingests merged commit objects directly from the Git object database using bare diffing and blob streaming, ensuring zero mutation of working trees, index locks, or checked-out branches.
- **Language Grammar Roadmap**:
  * **Phase 1 (Production JVM)**: Native Java and Kotlin AST diffing in-process via `tree-sitter-java` and `tree-sitter-kotlin` (integrated via `q-gate` library bindings), resolving symbol, method, and class modifications in sub-second time.
  * **Phase 2 (Native HAL & Daemons Roadmap)**: Integrates native C/C++ (`tree-sitter-cpp`) and AIDL/Protobuf (`tree-sitter-aidl`, `tree-sitter-protobuf`) grammars to support Motorola OEM Android Hardware Abstraction Layers (HALs), native camera/audio daemons, and IPC binder interface boundaries.
- **Debounce State Machine & Outbound Architectural Webhook**:
  * Enforces a 5-minute per-repository sliding debounce window with an explicit state machine (`Idle` ➔ `Accumulating` ➔ `Diffing` ➔ `Notifying`).
  * When structural API changes (public/protected methods, interface additions/modifications, type hierarchy shifts) are detected by the AST differential engine, Alexandria's outbound HTTP client dispatches a structured webhook event to Netflix/Orkes Conductor, triggering the `akashic_arch_reconciliation_pipeline` and `arch_reconciliation_worker` to synchronize `arch/<subsystem>.md` documentation.
- **Data Sanitization Engine**: Enforces an in-line "Redact & Retain" filter prior to vectorization and graph insertion, replacing matched secrets, credentials, and OEM signing tokens with a canonical redaction token while preserving AST structural connectivity.
- **Embedded State Store**: Uses an embedded SQLite database with Write-Ahead Logging (WAL) per repository as the authoritative single source of truth for all graph nodes, edges, and metadata.
- **Vector Storage & Inference Sidecar**: Decouples embedding generation into a local Text Embeddings Inference (TEI) sidecar running dense code models for symbol vectors, storing embeddings in an embedded vector index (`sqlite-vec`) keyed to node IDs. High-level cluster summaries leverage a local Gemma 2 2B model.
- **Lazy Artifact Projection**: Keeps `graph.json` and human-readable visual graphs un-materialized during continuous commit ingestion, rendering projections lazily on demand when accessed by agents, MCP tools, or operators.

## Testing Decisions

- **Definition of a Good Test**: Tests must exercise observable end-to-end behavior across the public system boundary rather than asserting on internal AST walker traversal states or private channel buffer sizes.
- **Primary Seam (Event-to-Projection Seam)**: A single high-level integration test seam where a simulated Gerrit `change-merged` event is dispatched to a fixture Git repository, verifying that the embedded SQLite store, sanitized vectors, and projected `graph.json` accurately capture the commit's symbol additions, deletions, and call edges without modifying the fixture working tree.
- **Prior Art**: Reuses testing conventions and tree-sitter AST fixture patterns from the `q-gate` test suite.

## Out of Scope

- Native Rust reimplementation of general-purpose non-JVM/non-HAL grammars (e.g., Python, shell scripts, HTML); these fall outside code graph AST indexing.
- Replacing or modifying the Akashic Vault repository structure or its incident/evidence markdown lifecycle.
- Serving public internet webhook traffic directly without an authenticating reverse proxy or SSH bastion.
- Dynamic runtime profiling or execution taint tracking.
