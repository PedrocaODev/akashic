  • Project domain teams maintain versioned Markdown specs and ADRs in repository vaults rather than relying on uncurated wiki pages.

09 // APPENDIX B: SECURITY & COMPLIANCE BATTLECARD (Q4)
Mandatory Tier-4 Sanitization Scrubs Secrets and Pseudonymizes Logcat PII
akashic-sanitize sits at the bottom of the crate DAG so no engine, vault, or RCA path can bypass it
Tier-4 Security Constraint (ADR 0007)
Because akashic-sanitize is at Tier 4, any outbound text to an embedding model or LLM MUST pass through it. The compiler enforces this dependency graph.
CodeProfile: Secret Replacement
- const String API_KEY = "sk-live-8a9b2..."; + const String API_KEY = "SAN_STR_TOKEN_A8F1";
AST-preserving secret replacement ensures syntax trees remain valid for analysis.
LogProfile: Semantic Pseudonymization
- Incoming call from +1-555-0198 (IMEI 354...) + Incoming call from <PHONE:US_VALID_10DIGIT> (IMEI <IMEI:VALID_15DIGIT>)
Format-preserving rules with per-session cryptographic salt allow the LLM to trace state across logs without seeing real PII (Phone, IMEI, MAC).
